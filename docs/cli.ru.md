# Справочник CLI

[English version](cli.en.md) · [Карта документации](README.ru.md)

```
python -m bp3d <command> [<object folder>] [options]
```

`PYTHONPATH` должен указывать на корень репозитория; запускать интерпретатором из `venv/`. Все команды, кроме `selftest` и `mannequin`, первым аргументом принимают папку объекта (папку со `spec.py`); путь приводится к абсолютному. Сообщения выводятся на русском, всегда в UTF-8. `sys.exit("…")` печатает сообщение в stderr и возвращает код выхода 1.

Реализация: `bp3d/__main__.py` — по одной функции `cmd_<name>()` на команду, argparse в `main()`.

| Команда | Назначение | Код выхода 1, когда |
|---|---|---|
| [`new`](#new) | Создать папку объекта со `spec.py` из стартового шаблона | `spec.py` уже существует |
| [`check`](#check) | Построить тела и проверить их | любая ошибка |
| [`draw`](#draw) | Лист чертежа: SVG, PNG, PDF | спецификация выбрасывает исключение |
| [`crop`](#crop) | Увеличенный фрагмент листа | нет браузера, нет SVG |
| [`approve`](#approve) | Записать апрув пользователя | — |
| [`build`](#build) | 3D-модель | нет апрува / апрув устарел, сбой Blender |
| [`render`](#render) | Презентационные рендеры | нет модели, сбой Blender |
| [`status`](#status) | Состояние апрува | никогда |
| [`posetest`](#posetest) | Одежда в наборе поз, таблица проникновений | проникновения выше порога, нет тела |
| [`body`](#body) | Мерки, ориентиры и роли костей тела | нет тела |
| [`mannequin`](#mannequin) | Пересобрать поставляемые тела | нет MPFB, сбой Blender |
| [`selftest`](#selftest) | Проверить инструмент на образцах | любой образец не прошёл |

---

## new

```
new <folder> [--code CODE] [--title "Title"]
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--code` | имя папки | Код объекта; становится `CODE = "…"` в спецификации |
| `--title` | название из шаблона | Становится `TITLE = "…"` в спецификации |

Копирует `examples/starter/spec.py` в `<folder>/spec.py` (переводы строк LF), заменяя строки `CODE = "XXX-000"` и `TITLE = "Ящик инструментальный"` буквально. Создаёт папку. Не перезаписывает существующий `spec.py`.

## check

```
check <folder> [-v]
```

Вызывает `build_model()` и проверяет каждую деталь. `-v` дополнительно перечисляет детали, состоящие из нескольких тел.

| Вид детали | Ошибки | Предупреждения |
|---|---|---|
| CAD (B-rep) | нет граней; `is_valid` ложно; грани есть, а тела нет (кроме групп `phantom`, `theory`); исключение при построении | — |
| Квадовый меш | неманифолдные рёбра; перевёрнутые рёбра; вырожденные грани; граничные рёбра (если меш не двусторонний); квады с соотношением сторон больше `ASPECT_MAX = 8` | отклонение от B-сплайна больше `BREP_DEV_MAX = 1.5` мм («добавьте рядов»); есть треугольники |
| Одежда (в модели есть тело) | вершина внутри тела (знаковое расстояние < −0.05 мм); меньше `garment.MIN_JOINT_LOOPS` петель поперёк зоны сустава | зазор до тела меньше половины отступа слоя |

Печатает ошибки в виде `ОШИБКА <key> (поз. N, group): …`, число деталей по группам, общий размер деталей `ext`, итоги по квадам и строку результата. Сама ничего не записывает; для спецификации одежды первая загрузка тела один раз запускает Blender и заполняет `.cache/`.

## draw

```
draw <folder> [--quick]
```

Строит модель, сливает настройки листа (`bp3d.json`, найденный вверх от папки, поверх него `sheet(model)`, затем `spec_hash`), один раз раскладывает лист (`drawing.build_body`) и записывает каждую тему (`drawing.wrap_svg`).

| Режим | Файлы в `<folder>/out/drawing/` |
|---|---|
| `--quick` | `<CODE>_print.svg`, `<CODE>_print.png` |
| полный | всё выше + `<CODE>.pdf` (тема print), `<CODE>_blueprint.svg`, `<CODE>_blueprint.png` |

`<CODE>` — это `model.code` до первого пробела. Размер листа — `size` из словаря листа, по умолчанию A1 `(841, 594)` мм. PNG и PDF печатает браузер без окна; без браузера записывается только SVG, и команда всё равно завершается успешно. Если браузер запустился, но трижды подряд оставил пустой PNG/PDF, `draw` и `crop` завершаются с ошибкой.

## crop

```
crop <folder> x y w h [--theme print|blueprint] [--scale PX_PER_MM] [--out FILE]
```

Фрагмент уже нарисованного листа, координаты в миллиметрах листа от левого верхнего угла. `--scale 0` (по умолчанию) вписывает фрагмент примерно в 1500×1100 px. Вывод по умолчанию: `<folder>/out/drawing/crop_<x>_<y>_<w>x<h>.png`. Нужен браузер. Берёт первый `*_<theme>.svg` в `out/drawing/`.

## approve

```
approve <folder> --by "<who>" [--note "<their words>"]
```

Записывает `<folder>/approved.json` с текущим хешем спецификации (см. [форматы файлов](file-formats.ru.md#approvedjson)). Всегда перезаписывает. Апрув даёт человек; агент записывает его только после того, как пользователь апрувнул своими словами.

## build

```
build <folder> [--force] [--out DIR] [--lin MM] [--ang RAD]
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--force` | выключен | Пропустить проверку апрува; результат — **черновик** (`draft: true` в отчёте) |
| `--out` | `<folder>/out/model` | Папка вывода. Черновики кладите в другое место: `render` и `posetest` берут модель из `out/model/` |
| `--lin` | `0.8` | Линейное отклонение тесселяции CAD-деталей, мм (одежда: не больше `0.3`) |
| `--ang` | `0.15` | Угловое отклонение, радианы |

Без `--force`: нет `approved.json` → отказ; сохранённый хеш ≠ текущему → отказ («перерисуйте и апрувните заново»).

Жёсткие предметы: `build.export_cad` + `build.export_quads` → `bl_build.py` в Blender. Одежда: `build.export_garment` (добавляет риг) → `bl_garment.py`. Имя вывода: `model.code` до первого пробела, `-` заменён на `_`. Получаемые файлы — [форматы файлов](file-formats.ru.md#результат-сборки-outmodel). Промежуточные `cad.glb` и `quads.npz` после этого удаляются; `manifest.json` и `blender.log` остаются.

Код выхода 0 даже при открытых мешах или предупреждениях — читайте напечатанную сводку и `report.json`.

## render

```
render <folder> [--color NAME] [--hero-only] [--model FILE.blend] [--out DIR] [--pose NAME] [--inspect KEYS] [--variant GROUP:NAME ...]
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--color` | `graphite` | Цвет краски для рендеров жёстких предметов: `graphite`, `teal`, `coral`, `sand`, `white`, `black` (не проверяется) |
| `--hero-only` | выключен | Только главный кадр (кадры) |
| `--model` | первый `out/model/*.blend` без `lookdev` в имени | Модель для рендера |
| `--out` | `<folder>/out/render` | Папка вывода |
| `--pose` | `hero` | Одежда: поза для кадров |
| `--variant` | первый в каждой группе | Одежда: варианты деталей для кадров, `группа:имя` (например `hood:down`) |
| `--inspect` | — | Одежда: осмотр формы перечисленных деталей (ключи через запятую): светлый матовый материал с картой нормалей вещи, свет со всех сторон, включая снизу, шесть ракурсов `inspect_front/back/left/right/top/bottom.png`; поза покоя или `--pose` |

Жёсткие предметы: `bl_render.py` в Blender (профиль пользователя, а не заводские настройки), Cycles, шесть кадров; записывает `render_<color>.json`. Одежда: `bl_pose.py` — тун спереди/сзади (+ сбоку, поза покоя, матовый, каркас без `--hero-only`); записывает `render.json`. Оба копируют `spec_hash` и `draft` из `report.json` модели.

## status

```
status <folder>
```

Печатает дату и автора апрува и то, актуален он (`актуален`) или устарел (`УСТАРЕЛ`), либо что апрува нет; затем текущий хеш. Всегда возвращает 0. Для спецификации, которая импортирует `bp3d.body`/`from bp3d import …`, вычисление хеша запускает спецификацию (и может один раз экспортировать тело через Blender).

## posetest

```
posetest <folder> [--poses NAME ...] [--show MM] [--no-render] [--model FILE.blend] [--out DIR]
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--poses` | все, кроме `hero` | Позы для проверки (см. [руководство → Одежда](manual.ru.md#одежда)) |
| `--show` | `1.0` | Скрыть строки мельче этого числа мм (строки коллайдеров показываются всегда) |
| `--no-render` | выключен | Только таблица, без Blender |
| `--model` | первый `out/model/*.blend` | Модель для рендеров |
| `--out` | `<folder>/out/posetest` | Папка вывода |

Ставит одежду в позу тем же линейным скиннингом и с теми же весами, что идут в FBX, успокаивает цепочки пружин, измеряет проникновения (`posetest.run`). Печатает таблицу «поза → деталь → вид → мм → вершины → место»; строки выше порога помечены `!`. При собранной модели и без `--no-render` рендерит каждую позу (`pose_<name>.png`) и до четырёх худших мест (`worst<n>_<pose>_<part>.png`) через `bl_pose.py`. Записывает `report.json`. Код выхода 1, если хоть одна строка выше своего порога.

## body

```
body <body file | object folder>
```

Загружает тело (`.blend`/`.glb`/`.fbx` с одной арматурой) или первое тело, которое использует спецификация в папке, и печатает число вершин/треугольников/костей, роли костей, мерки и параметры конечностей `elbow_t`, `knee_t`. Проверка на здравость для своих тел.

## mannequin

```
mannequin [--kind mpfb|dummy]
```

Пересобирает поставляемое тело **внутри репозитория** (`bodies/`):
- `mpfb` (по умолчанию) — `mannequin_f` из `bodies/mannequin_f/macro.json` через MPFB (`bl_mpfb.py`). Нужен MPFB в `.mpfb/blender_user` или в профиле, заданном `BP3D_MPFB` (`scripts/install_mpfb.ps1`).
- `dummy` — `dummy_t` из `bp3d/mannequin.py` (`bl_mannequin.py`).

Каждый апрув одежды, построенной на пересобранном теле, становится устаревшим.

## selftest

```
selftest [--draw] [--only NAME ...]
```

Для каждой `examples/<name>/` со `spec.py` (по алфавиту), в отдельном процессе: `check`; с `--draw` ещё `draw --quick` (проходит, только если появился свежий `*_print.png`); для спецификаций, использующих `bp3d.garment`, ещё `posetest --no-render`. Упавший шаг останавливает этот образец и печатает хвост его вывода. Итоговая строка — `образцы в порядке` или список сбоев. Пишет в `examples/*/out/`.

## Переменные окружения

| Переменная | Кто использует | Значение |
|---|---|---|
| `BP3D_BLENDER` | всё, что запускает Blender | Полный путь к исполняемому файлу Blender (проверяется первым) |
| `BP3D_BROWSER` | `draw`, `crop` | Полный путь к Edge/Chrome/Chromium |
| `BP3D_MPFB` | `mannequin --kind mpfb` | Папка пользовательских ресурсов Blender с установленным MPFB |
| `BP3D_UV` | `scripts/install.*` | Путь к `uv`, если его нет в `PATH` |
| `PYTHONPATH` | все | Корень репозитория (инструмент не ставится через pip) |
