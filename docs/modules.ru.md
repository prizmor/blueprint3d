# Справочник модулей

[English version](modules.en.md) · [Карта документации](README.ru.md)

За что отвечает каждый модуль в `bp3d/`, его публичный интерфейс, от чего он зависит и на что обратить внимание. Использование API спецификации для пользователя (примеры, правила, выведенные на практике) — в [руководстве](manual.ru.md); эта страница — для тех, кто меняет код.

| Модуль | Строк | Среда | Хешируется* | Ответственность |
|---|---|---|---|---|
| [`__main__.py`](#__main__py) | ~670 | инструмент | нет | CLI, загрузка спецификации, апрув, конфигурация проекта, браузер, selftest |
| [`model.py`](#modelpy) | ~120 | инструмент | нет | `Model`, `Part`, отделки, палитра, BOM |
| [`kit.py`](#kitpy) | ~600 | инструмент | **да** | Контуры, призмы, лофты, булевы операции, B-сплайн-поверхности, оболочки |
| [`mesh.py`](#meshpy) | ~780 | инструмент | **да** | Квадовые меши из сеток, UV-острова, толщина, упаковка атласа, сечение мешей |
| [`drawing.py`](#drawingpy) | ~1030 | инструмент | нет | Проекция, HLR, разрезы, обозначения, таблицы, SVG |
| [`build.py`](#buildpy) | ~170 | инструмент | нет | Поиск Blender, экспорт для Blender, запуск скриптов |
| [`body.py`](#bodypy) | ~830 | инструмент | одежда | Тело с ригом как массивы: роли, ориентиры, мерки, кольца и сетки, позы |
| [`garment.py`](#garmentpy) | ~920 | инструмент | одежда | Блоки одежды `Outfit` |
| [`rig.py`](#rigpy) | ~345 | инструмент | одежда | Перенос весов, цепочки пружин, коллайдеры, скрытие тела, экспорт динамики |
| [`posetest.py`](#posetestpy) | ~280 | инструмент | нет | Библиотека поз, равновесие пружин, измерение проникновений |
| [`mannequin.py`](#mannequinpy) | ~140 | инструмент | нет | Тело `dummy_t`, собранное кодом |
| [`bl_*.py`](#скрипты-blender) | ~1650 | Blender | нет | Сборка сцены, экспорт, атлас, рендеры, экспорт тела, пересборка манекена |

## `__main__.py`

**Отвечает за:** командную строку и всё, что связывает этапы.

- `main()` — argparse; переключает stdout/stderr на UTF-8; передаёт управление в `cmd_<name>(obj, args)`. Справочник: [CLI](cli.ru.md).
- `load_spec(obj)` — импортирует `<obj>/spec.py` как модуль `bp3d_spec`, добавляет `obj` в `sys.path` (так спецификация может импортировать модули рядом с собой), кэширует по пути в `_specs`.
- `spec_hash(obj)` — хеш апрува (см. [архитектуру](architecture.ru.md#апрув-и-воспроизводимость)). `spec_bodies(obj)` находит глобальные `Body` спецификации; спецификация запускается, только если в её тексте упоминается `bp3d.body` или `from bp3d import`.
- `project_config(obj)` — первый `bp3d.json` вверх от папки объекта.
- `check_quad`, `check_garment` — правила `check`; пороги `ASPECT_MAX = 8.0`, `BREP_DEV_MAX = 1.5` мм.
- `browser()`, `render_svg()` — поиск браузера без интерфейса и SVG → PNG/PDF.
- `_run_pose()`, `_garment_blend()` — связка с `bl_pose.py`.
- `cmd_selftest` — запускает каждый шаг образца в отдельном процессе с `PYTHONPATH` = корень репозитория.

Зависит от: `build`, `drawing`, лениво — `body`, `posetest`, `mannequin`.

## `model.py`

**Отвечает за:** описание объекта в памяти.

- `FINISHES` — `{finish: dict(gray, metal, rough)}`: `paint, chrome, metal, plastic, rubber, glass, lamp, amber, cloth, satin, leather`. Задаёт серую модель и цвета атласа; презентационные материалы живут в `bl_render.py`/`bl_pose.py`.
- `PALETTE` — 17 именованных цветов (предложение; выбирает пользователь). `rgb(color)` принимает имя из палитры, `#RRGGBB` или кортеж и возвращает sRGB во float 0–1.
- `Part` — dataclass: `key, pos, name, material, shape, finish="paint", group="ext", note, count=True, mesh="cad", quad, bind, dynamics, layer=0, hides, color, pattern, info`.
- `Model(code, title, subtitle="", parts=[], bom_extra={}, body=None)`:
  - `add(...)` проверяет уникальность ключа и отделку; `QuadMesh`, переданный как `shape`, становится `quad`, а `shape` становится `quad.brep()`, `mesh` по умолчанию `"quad"`; возвращает B-rep.
  - `ext()`, `internal()`, `bom()` (пропускает `phantom`/`theory`, суммирует количество по `count`, применяет `bom_extra`).

Группы: `ext` — видимые; `int` — внутренние (штриховой линией, отдельная коллекция в 3D); `glass` (не проецируется, есть в разрезах, прозрачное в рендерах); `phantom` (окружение: тонкая линия фантома, нет в BOM и в 3D); `theory` (теоретические поверхности: только сетки/планы линий).

## `kit.py`

**Отвечает за:** построение B-rep на build123d/OpenCascade. Единицы — мм. **Хешируется.**

| Группа | API |
|---|---|
| Контуры | `Path(start)` с `.L(*pts)`, `.A(c, r, a1)` (≤ 180° за вызов), `.S(*pts)`, `.close()`, `.wire(to3)`, `.sample(step)`; точка `(u, v, r)` скругляет вершину (только между двумя прямыми; радиус молча ограничивается). Вспомогательные `poly`, `sym`, `arcpts`, `rect`, `circle_path`, `ellipse_path` (приближение сплайном), `hexagon` |
| Тела | `prism_xz/yz/xy(path, a, b, grow=0)`; `tri(side, front, top)` — пересечение призм видов; `loft_x(sections, centripetal=False, max_degree=8)`; `revolve_about`; `cyl`; `box` |
| Булевы операции, размещение | `union`, `cut`, `mirror_y`, `heal` (чинит, если тело некорректно, никогда не бросает исключение), `surface_x` (луч, чтобы посадить детали) |
| Одномерные линии формы | `lerp`, `interp`, `mono` (монотонная кубическая, без перелёта), `smooth` (Catmull-Rom), `hermite` |
| Сетки `(nu, nv, 3)` | `coons`, `resample`, `grid_of(fn, nu, nv)` (ряды передискретизируются по длине, поэтому общие границы совпадают), `map_grid`, `mirror_grid`, `grid_normals`, `offset_grid` (по умолчанию +нормаль) |
| Поверхности | `bspline_surface(G)` — собственная кубическая интерполяция not-a-knot (scipy), ≥ 4×4 точек; `surface_face`; `skin(bands, t)` — оболочка толщиной t в сторону −нормали со скошенными общими рядами, сшитая; при неудаче — по одному телу на полосу; `section_curves` |

Обратите внимание: `bspline_surface` намеренно **не** использует `GeomAPI_PointsToBSplineSurface` (несимметрична на зеркальных сетках). `offset_grid` идёт по +нормали, `skin` — по −нормали.

## `mesh.py`

**Отвечает за:** полигональные меши из тех же сеток, для игровой топологии. **Хешируется.**

- Метки `OUTER, INNER, RIM = 0, 1, 2`.
- `Patch(G, closed_u, closed_v, name, uv_scale)` — одна сетка = один UV-остров, развёрнутый по средним длинам рядов (мм). Нормаль `du × dv` наружу. `deviation()` сравнивает центр ячейки кубического сплайна с квадом.
- `QuadMesh` — `V (N,3)`, `F (M,4)` (треугольник: последний индекс −1), `UV (M,4,2)` по углам в мм острова, `face_island`, `face_tag`, `islands`, `vpatch`, `vuv`, `vside`, `sharp`, `patches`, `thickness`, `two_sided`.
  - `from_patches(patches, weld=1e-3, sharp_borders=False)` → `_weld` (KD-дерево, только одна сторона; грани, схлопнувшиеся до 3 вершин, становятся полюсами).
  - `solidify(t, inner_uv=0.5)` — внутренний слой вдоль нормалей вершин со скосом (≤ 2t), квады кромки на открытых рёбрах; внутренние грани сохраняют первую вершину, чтобы оба слоя делили диагональ триангуляции; острова кромки делят одну полосу.
  - `brep()` — составное тело из B-сплайн-граней **только внешнего слоя, нулевой толщины** (для видов); разрезы квадовых деталей вместо этого режут меш.
  - `check(aspect_max=8.0)`, `uv_stretch()`, `deviation()`, `counts()`, `merged`, `transformed`, `mirrored_y`, `triangles`.
- Построители: `quad_skin(bands, t)`, `quad_shell`, `quad_tube(G, caps)`, `quad_sweep(profile, path, corners)`, `revolve_quad`, `box_quad`, `cap_grid` (чётное кольцо).
- Генераторы сеток: `spacing(n, dense=[(c, w, k)])` (плавная гауссова плотность), `resample_closed/open`, `frames`, `sweep_grid`, `loft_grid`, `revolve_grid`.
- `slice_mesh(V, T, origin, normal)` — полилинии сечения плоскостью.
- `pack_islands(sizes, pad=0.012)` — упаковка полками в квадрат с одним масштабом для всех островов (одинаковая плотность текселей).
- `MeshShape(V, T)` — готовый треугольный меш как окружение (тело под одеждой на чертеже).

## `drawing.py`

**Отвечает за:** лист. Не хешируется — изменение чертежа никогда не делает апрувы недействительными.

Конвейер: `build_body(model, S)` → `Sheet` (фрагменты SVG, 1 единица = 1 мм листа) → `wrap_svg(sheet, theme, title)`.

Порядок `build_body`: виды → планы → разрезы → выносные виды → обозначения (`dims`, `dias`, `radii`, `angles`, `lines`, `balloons`, `notes`, `cuts`, `texts`) → таблица зазоров → таблицы одежды (мерки, слои, динамика) → перечень позиций → технические требования → легенда → рамка и штамп.

- **Проекция.** `CAMERAS` — `{kind: (direction, up)}` для `side, front, top, rear, right, iso`; спецификации могут добавлять записи. `ViewProj(kind, look_at, top_up)` калибрует двумерное изображение осей и проецирует формы; `MODE = "exact"` (HLR OpenCascade, допуск хорды 0.06 мм) или `"poly"` (`HLRBRep_PolyAlgo` на меше, гораздо быстрее на сотнях сплайновых тел); пустой точный результат откатывается на poly. `FreeProj` — для произвольных плоскостей разреза; `Placed(proj, k, at)` переносит на лист.
- **Группы.** `ext` — с HLR; `int` проецируется отдельно и рисуется невидимыми линиями; `glass` не проецируется, если не запрошено; `phantom` — тонкая линия фантома (меши — через программный буфер глубины, `mesh_outline`); `theory` — только через `grid`/`plans`.
- **Разрезы.** Плоскости осей или `("free", origin, normal[, up])`; CAD-детали — пересечением B-rep с плоскостью, квадовые детали и меши — через `slice_mesh`; тонкие сечения (2·площадь/периметр < 1.4 мм листа) заливаются сплошь (ГОСТ 2.306), остальные штрихуются с чередованием; `behind` добавляет то, что лежит за плоскостью.
- **Классы линий** `m` (0.45, видимая), `m2`, `h` (невидимая), `c` (осевая), `t`, `d` (размерная), `g` (сетка), `ph` (фантом), `sec`, `cut`, `dyn*`; темы `print` и `blueprint`; набор наклонных шрифтов в стиле ГОСТ.
- **Штамп** — поля из словаря листа: `title_lines`, `doc_type`, `lit`, `scale` (только текст — масштаб вида задаёт `k`), `org`, `author`, `approved_by`, `date`, `spec_hash`.

Обратите внимание: `ViewProj.MODE`/`DEFLECTION` — на уровне класса и выставляются каждым `build_body`; выносные виды переиспользуют полилинии родительского вида (без дополнительного разрешения); отсутствие `title_at`, `gaps_at`, `tech_at` вызывает `KeyError`.

## `build.py`

**Отвечает за:** передачу модели в Blender.

- `find_blender()` — `BP3D_BLENDER`, Steam, `Program Files\Blender Foundation\Blender 5.3`, приложение macOS, `PATH`.
- `export_cad(model, out, lin, ang)` — CAD-детали в `cad.glb` (метры), записи манифеста для всех деталей, кроме `phantom`/`theory`.
- `export_quads(model, out, atlas_px=2048)` — квадовые детали в `quads.npz`, упаковка атласа и цвета/узоры островов.
- `export_garment(model, out, name)` — всё перечисленное плюс `Rig(model).export()` в манифест и `<name>_dynamics.json`.
- `run_blender(manifest, glb, out, name, script, extra)` — запускает `bl_*.py` с `-b --factory-startup`, пишет `blender.log`, требует `BP3D_DONE` и `report.json`.
- `quad_stats(part)` — показатели качества для `check` и отчёта.

## `body.py`

**Отвечает за:** тело с ригом в виде данных numpy. **Хешируется для спецификаций одежды.**

- `load(path, roles=None, landmarks=None)` → `Body`; экспортирует через `bl_body.py` один раз на файл тела в `.cache/body_<sha16>.npz`; запоминается по `source_hash`. Константы `MANNEQUIN_F`, `DUMMY_T`.
- **Роли.** `guess_roles(names, parent)` сопоставляет кости с `hips, spine, chest, upper_chest, neck, head, clavicle/upper_arm/forearm/hand/thigh/shin/foot/toe _L/_R` по токенам имён (Unity Humanoid, Mixamo, UE/MakeHuman game_engine, Rigify); побеждает самое неглубокое совпадение; кости с `twist, roll, ik, pole, helper, end, ctrl, target…` пропускаются. Кости без роли наследуют роль ближайшего предка (пальцы → кисть).
- **Ориентиры** `lm`: высоты `waist, bust, underbust, hips, crotch, armpit, neck_base, head_base, knee, ankle, height`; точки суставов `shoulder/elbow/wrist/hip/knee/ankle/armpit/shoulder_top _L/_R`; `elbow_t`, `knee_t`. Вычисляются по костям, лучам и горизонтальным сечениям (экстремумы периметра).
- **Мерки** `measures`: обхваты, как сантиметровой лентой (выпуклая оболочка), и длины, округлённые до 0.1 мм.
- **Геометрические помощники:** `closest(P)` (знаковое расстояние, точка, треугольник, барицентрические координаты), `weights_at(P)`, `push_out(G, clearance)`, `section`, `ring`, `torso_ring/torso_grid`, `limb_point/limb_frame/limb_ring/limb_grid`, `nearest_landmark`.
- **Позы:** `pose(spec)`, `pose_on(skel, spec)` с `("to", vec)`, `("bend", deg, vec)`, `[(axis, deg)]`, `"_root"`; ключи без стороны применяются к обеим сторонам зеркально.
- `Skeleton`, `Surface`, `skin_points` (линейный скиннинг).

## `garment.py`

**Отвечает за:** блоки одежды. **Хешируется для спецификаций одежды.**

- Константы: `LAYER_GAP = {1: 2, 2: 6, 3: 10, 4: 14}` мм, `ROW_STEP = 20`, `MIN_JOINT_LOOPS = 3`, пресеты `DYNAMICS = {stiff, soft, rigid}` (жёсткость, затухание, гравитация, радиус).
- `Piece(patches, t, edges, solid, joints, name)` — сетки внешней поверхности с именованными краями, к которым крепятся другие блоки; суставы — для проверки петель у суставов.
- `Outfit(model, body, cols=48)` — выставляет `model.body`, добавляет тело как деталь `phantom`; `add(key, pos, name, material, pieces, finish="cloth", layer, bind="auto", dynamics, hides, pattern, …)` сваривает куски в одну квадовую деталь с толщиной и заполняет `info` (зазор, суставы, области, подкладка).
- Блоки: `tube`, `bodice`, `sleeve`, `skirt`, `pants`, `stocking`, `glove`, `collar`, `cuff`, `hem_band`, `band`, `piping`, `belt`, `buckle`, `button(s)`, `lacing`, `ribbon`, `bow`, `shoe`; помощники `waist_ring`, `push_over`, `over_radius`, `front_point`. Параметры и края: руководство → Одежда.

## `rig.py`

**Отвечает за:** привязку одежды к скелету. **Хешируется для спецификаций одежды.**

- `Rig(model)` — расширяет скелет тела костями с пружиной, вычисляет веса для каждой квадовой детали, жёсткую привязку для `bind="<bone or role>"` и CAD-деталей, коллайдеры, скрытые полигоны тела.
- Перенос весов `_auto`: ограничение по стороне для каждой вершины (левые вершины никогда не берут веса правых конечностей), необязательное ограничение по области/роли, барицентрические веса от ближайшего треугольника тела, сглаживание у краёв, смешивание с весами цепочек пружин, 4 наибольших влияния.
- `chains(part, body)` — цепочки пружин из `dynamics` детали (ключи `patch, chains, bones, v0, v1, blend, parent, follow, radius, colliders, path`); имена костей `<key>_d<zone>p<k>c<chain>_<i>`.
- `body_colliders(body)` — капсулы для бёдер, голеней, плеч, предплечий, таза, торса, головы.
- `_hidden` — полигоны тела, полностью закрытые одеждой с `hides` (`reach` 14 мм, `margin` 18 мм от краёв одежды).
- `export(arrays)` (веса в npz, раздел rig в манифесте), `dynamics_manifest(name)` → [`<name>_dynamics.json`](file-formats.ru.md#name_dynamicsjson).

## `posetest.py`

**Отвечает за:** проверку одежды в движении без игрового движка.

- `POSES` — `rest, t_pose, arms_down, arms_up, arms_forward, elbows_bent, squat, wide_step, side_step, bend_forward, twist, sit`; презентационная поза `HERO` (исключена из тестов).
- `solve(rig, pose)` — кости тела из позы; цепочки пружин в **статическом равновесии** (пружина к ориентации покоя, гравитация, выталкивание из коллайдеров, длины сегментов сохраняются). Затухание не используется.
- `run(model, poses)` — делает скиннинг каждой детали весами FBX и измеряет: `body` (вершина под кожей своей области), `layer` (верхний слой под внешней поверхностью нижнего), `collider` (насколько коллайдер вытолкнул цепочку). Глубины больше 30 мм игнорируются как «другая сторона».
- Цепочки одной зоны связаны поперёк: сустав идёт за большим смещением соседей по кольцу на долю `LATERAL = 0.75`.
- Пороги `PEN_BODY = PEN_LAYER = 4.0` мм, `PEN_EXTREME = 12.0` мм в `sit, squat, elbows_bent`; `limit(pose, kind)`.
- `bone_matrices(rig, pose)` — матрица 4×4 на кость для `bl_pose.py`.

## `mannequin.py`

**Отвечает за:** тело `dummy_t`, собранное кодом, — торс из колец-суперэллипсов, трубки конечностей, эллипсоиды для головы, кистей, груди, ягодиц; `skeleton()` с 22 костями Unity Humanoid. Пересобирается командой `mannequin --kind dummy` (воксельный ремеш, сглаживание и автоматические веса делаются в `bl_mannequin.py`).

## Скрипты Blender

Все работают внутри Blender, читают `sys.argv` после `--` и в конце печатают признак. Контракты: [архитектура → модель процессов](architecture.ru.md#модель-процессов); файлы: [форматы файлов](file-formats.ru.md).

| Скрипт | Кем вызывается | Что делает |
|---|---|---|

## Глобальное состояние

Известное состояние на уровне модулей — новое не добавлять:

| Состояние | Модуль | Влияние |
|---|---|---|
| кэш `_specs`, вставки в `sys.path` | `__main__` | один экземпляр модуля спецификации на процесс; папка спецификации остаётся доступной для импорта |
| `ViewProj.MODE`, `ViewProj.DEFLECTION` | `drawing` | выставляются каждым `build_body`, никогда не восстанавливаются |
| `CAMERAS` | `drawing` | спецификации могут добавлять направления камер |
| `_loaded` | `body` | тела запоминаются по `source_hash` |
| `QuadMesh._brep` | `mesh` | кэшированный B-rep, сбрасывается `transformed()` |

## Известные проблемы

Найдены при написании этой документации; каждая — кандидат на pull request.

- Индексы полигонов для скрытия тела вычисляются по отдельным мешам в `bl_body.py`, а применяются после объединения мешей в `bl_garment.py`; у тела из нескольких мешей скрытые полигоны могут попасть не на те грани.
- Ключ `.cache/body_*.npz` — только хеш файла тела: после изменения `bl_body.py` удалите `.cache/`.
- `bl_build.py` и `bl_garment.py` сохраняют модели через `save_as_mainfile`, который записывает абсолютные пути в `.blend` пользователя (тела используют `save_clean`).
- `bl_render.py` сопоставляет материалы по имени и не знает отделок `cloth`/`satin`/`leather`; его кадры `lamp`/`wheel` рассчитаны на транспорт.
- `bl_inspect.py` нужна камера сцены, а `bl_garment.py` удаляет её перед сохранением.
- Устаревшие docstring: `__main__` (хеш покрывает больше, чем `spec.py + kit.py`), `bl_common` (упоминает `bl_toon`), `bl_mpfb` (утверждает, что пишет GLB).
- `damping` цепочек пружин экспортируется, но не используется в `posetest`.
- Файлы открываются без закрытия в нескольких вызовах `json.load(open(...))` в `__main__.py`.
- У подпроцессов (Blender, браузер) нет тайм-аута.
