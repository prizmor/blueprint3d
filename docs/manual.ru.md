# Blueprint3D — полное руководство

Инструмент 3D-моделей для игр: жёсткие предметы (транспорт, оружие, снаряжение, мебель, постройки) и одежда персонажей на теле с ригом. Объект описывается один раз — параметрической спецификацией на Python (`spec.py`). Из неё получаются два представления:

| Представление | Что это | Как получено |
|---|---|---|
| Чертёж | Лист ГОСТ: SVG, PNG, PDF, белый и «синька» | Проекции тел со скрытыми линиями, сечения плоскостями, выносные виды, размеры, выноски, спецификация |
| 3D-модель | `.blend`, `.fbx`, `.glb`, рендеры, отчёт | Те же тела → Blender в фоне. Два пути меша: CAD-триангуляция (серая модель) или квадовый меш с развёрткой прямо из сеток построения. Для одежды — ещё арматура, веса, кости с пружиной |

Чертёж и модель совпадают по построению: оба сняты с одних тел. Нарисовать на чертеже не то, что в модели, нельзя.

Порядок работы для ИИ-агента — [`AGENTS.md`](../AGENTS.md). Английская версия руководства — [`manual.en.md`](manual.en.md).

Образцы — пробные объекты, на которых инструмент отлаживался, а не игровые ассеты: их размеры — оценки, чертежи не апрувнуты. Из них берут приёмы и устройство листа, но не форму. Коды `EX-…` заняты ими — своим объектам их не давать.

## Установка

Нужны: Git с Git LFS (тела в `bodies/` — файлы LFS), Python 3.12 (или [uv](https://docs.astral.sh/uv/) — он поставит Python сам), Blender 5.3 для 3D-этапа, Edge, Chrome или Chromium для PNG и PDF чертежа.

```powershell
git lfs install
git clone https://github.com/prizmor/blueprint3d.git
cd blueprint3d
powershell -ExecutionPolicy Bypass -File scripts\install.ps1     # Linux, macOS: sh scripts/install.sh
```

Скрипт ставит `venv/` (Python 3.12, build123d 0.13, numpy, scipy) и проверяет, что Blender и браузер находятся. Blender ищется по переменной `BP3D_BLENDER`, в Steam (`...\steamapps\common\Blender\blender.exe`), в `C:\Program Files\Blender Foundation\Blender 5.3\`, в `/Applications/Blender.app` и в `PATH`. Браузер — по `BP3D_BROWSER`, затем Edge, Chrome, Chromium. Чертёж без браузера тоже рисуется, но только в SVG.

MPFB (`scripts\install_mpfb.ps1`) нужен только чтобы пересобрать манекен; готовое тело лежит в `bodies/`. MPFB ставится в отдельный профиль Blender `.mpfb/` внутри репозитория; свой профиль можно указать в `BP3D_MPFB`.

**Настройки проекта.** Файл `bp3d.json` в папке объекта или выше по дереву (обычно в корне вашего проекта) задаёт значения листа по умолчанию, например `{"org": "СТУДИЯ", "author": "Иванов"}` — надпись в штампе. `sheet()` спецификации их перекрывает. В хеш апрува файл не входит.

## Команды

Запуск из любой папки: `PYTHONPATH` указывает на корень репозитория инструмента, путь к объекту — любой.

```powershell
$env:PYTHONPATH="C:\путь\к\blueprint3d"; $py="C:\путь\к\blueprint3d\venv\Scripts\python.exe"
& $py -m bp3d check   art\blueprints\<КОД>
```

Linux и macOS: `PYTHONPATH=/путь/к/blueprint3d /путь/к/blueprint3d/venv/bin/python -m bp3d check art/blueprints/<КОД>`.

| Команда | Что делает |
|---|---|
| `new <папка> [--code КОД] [--title "Название"]` | Создаёт папку объекта со `spec.py` из шаблона `examples/starter`. Код по умолчанию — имя папки |
| `check <папка>` | Собирает тела и проверяет их: невалидные, пустые, без замкнутого тела; печатает габариты. Квадовые детали: замкнутость, манифолдность, обход граней, вырожденные и вытянутые квады, отклонение от B-rep. Одежда: зазор до тела и петли у суставов. Код возврата 1 при ошибках |
| `draw <папка> [--quick]` | Чертёж. `--quick` — только белый PNG, для итераций |
| `crop <папка> x y w h [--out файл]` | Участок листа крупно (мм листа) — для самопроверки по зонам |
| `approve <папка> --by "<кто>" --note "<цитата>"` | Записывает апрув: хеш `spec.py` и модулей построения (для одежды — и файла тела) |
| `build <папка> [--force] [--out папка]` | 3D-модель. Без `--force` отказывает, если чертёж не апрувнут или спецификация изменилась |
| `render <папка> [--color цвет] [--hero-only] [--model файл.blend] [--pose поза]` | Презентационный рендер. Для одежды — поза показа в toon-стиле и матовый кадр |
| `status <папка>` | Состояние апрува |
| `posetest <папка> [--poses ...] [--show мм] [--no-render] [--model файл.blend]` | Одежда в наборе поз: таблица проникновений и рендеры худших случаев. Код возврата 1, если есть строки выше порога |
| `body <файл тела или папка>` | Мерки, ориентиры и роли костей тела |
| `mannequin [--kind mpfb\|dummy]` | Пересобрать тела инструмента в `bodies/` |
| `selftest [--draw] [--only имя ...]` | Проверка самого инструмента: `check` (с `--draw` — и черновой лист) для каждого образца в `examples/`, для образца одежды — ещё `posetest`. Код возврата 1, если хоть один не прошёл |

## Порядок работы

1. **Паспорт.** Назначение, реальные габариты, опорные размеры, что видимое и что внутреннее. Чего пользователь не задал — помечать как предложение, не выдумывать молча.
2. **Спецификация.** `new <папка объекта>` кладёт рабочий шаблон; геометрия и лист шаблона заменяются своими. `build_model()` возвращает `Model` с деталями, `sheet(model)` — описание листа.
3. **`check`.** Исправить все ошибки до отрисовки.
4. **`draw --quick`** и самопроверка чертежа по зонам через `crop` (чеклист ниже).
5. **Черновая 3D до показа.** `build --force --out <временная папка>`, посмотреть рендеры. Сборка находит ошибки, которых не видно в линиях: просветы, детали наизнанку, пересечения.
6. **`draw`** полный и показ пользователю. Апрув даёт только пользователь словами в чате; записать `approve` с цитатой.
7. **`build`** без `--force`: проверить отчёт (незамкнутые меши, отклонения габаритов) и рендеры глазами.
8. **`render`** — если нужен показ в цвете.

Любая правка `spec.py`, `kit.py` или `mesh.py` после апрува делает его устаревшим: чертёж перерисовывается и апрувится заново. Для одежды в хеш входят ещё `body.py`, `garment.py`, `rig.py` и файл тела. `--force` — только черновик для собственной проверки, не результат для пользователя.

Для одежды порядок тот же с добавками: мерки тела в начале и `posetest` после черновой сборки — `new → check → draw --quick → crop → build --force → posetest → исправления → draw → апрув → build → posetest → render`. Подробно — раздел «Одежда».

## Спецификация объекта

```python
from bp3d.kit import ...
from bp3d.model import Model

def build_model():
    M = Model(code="XXX-000", title="Название")
    M.add("key", 1, "Наименование", "Материал", shape, finish="paint", group="ext")
    return M

def sheet(model):
    return dict(size=(841, 594), scale="1:8", views=[...], sections=[...], ...)
```

Оси: X — назад от передней точки, Y — влево, Z — вверх от земли, миллиметры. В Blender перёд смотрит в −Y.

**Отделка** (`finish`) задаёт тип материала: серый оттенок в модели и материал в рендере — `paint`, `chrome`, `metal`, `plastic`, `rubber`, `glass`, `lamp`, `amber`, для одежды `cloth` (ткань матовая), `satin` (ткань с блеском), `leather` (кожа). Поле `material` — текст для спецификации на листе («Хлопок»), на вид не влияет.

**Поля детали** (`Model.add(...)`, все необязательные — старые спецификации работают как раньше):

| Поле | Значение |
|---|---|
| `mesh` | `"cad"` — CAD-триангуляция тела (по умолчанию); `"quad"` — квадовый меш. Ставится само, если вместо тела передан `QuadMesh` |
| `color` | Цвет: имя из `model.PALETTE`, `"#RRGGBB"` или `(r, g, b)`. Без цвета деталь серая по отделке. Палитра — предложение, цвет выбирает пользователь |
| `pattern` | Узор или список узоров для квадовой детали, запекается в атлас по UV: `dict(kind="stripe", dir="v", pitch, width, color)`, `"check"` (`style="gingham"\|"checker"`), `"dots"` (`pitch`, `r`), `"fill"` — весь остров одним цветом (вместе с `patch`: подошва, вставка), `"trim"` — кант по краю острова (`edges=("v1",)`, `width`). `patch="имя"` — только на лоскутах с таким началом имени |
| `bind` | Привязка к скелету: `"auto"` — веса с тела; роль или имя кости (`"hips"`) — жёсткая деталь на одной кости |
| `dynamics` | Кости с пружиной: `"stiff"` (пружинит, держит форму), `"soft"` (обвисает), `"rigid"`/`None` или словарь — см. «Одежда» |
| `layer` | Слой одежды 1…4 (0 — не одежда) |
| `hides` | `True` — тело под деталью скрывается |

**Группы деталей** (`group`):

| Группа | На видах | В разрезах | В спецификации и 3D |
|---|---|---|---|
| `ext` | видимый контур | да | да |
| `int` | штриховыми | да | да, коллекция `internal`, на рендерах скрыта |
| `glass` | не проецируется и ничего не заслоняет | да | да, в рендере прозрачная |
| `phantom` | тонкая штрихпунктирная с двумя точками | нет | нет |
| `theory` | нет (только сетка сечений и обводы) | нет | нет |

Детали одной позиции, которые не увеличивают количество, — `count=False`. Коды объектов не переиспользовать.

## Геометрия

### Простые тела
- `Path` — контур из прямых (`L`), дуг (`A`, не больше 180° за вызов) и сплайнов (`S`); точка `(u, v, r)` скругляет вершину настоящей дугой. Не дискретизировать кривые ломаными: каждая грань даст лишнюю линию на чертеже.
- `tri(side, front, top)` — пересечение призм видов; годится для корпусов и простых панелей.
- `prism_xz`, `prism_yz`, `prism_xy` с `grow` — вытягивание контура, смещение контура для зазоров.
- `loft_x(..., centripetal=True)`, `revolve_about`, `cyl`, `box`, `cut`, `union`, `mirror_y`.

### Поверхности двоякой кривизны
Пересечение призм видов даёт «коробку», один лофт по сечениям — «мыло». Кузовные панели строятся лоскутами:

1. Форма задаётся функциями — дизайн-линиями и сечениями (`mono`, `hermite`).
2. Каждая гладкая зона — сетка точек: `grid_of`, `coons`, `map_grid`.
3. Панель — оболочка с толщиной `skin([лоскуты], t)`. Общий ряд точек соседних лоскутов — характерное ребро; оно само становится линией чертежа.
4. Зазоры — смещением границ лоскутов, не вырезанием.
5. Детали «по месту» (рамки, ламели, вставки) — пересечение контура вида со слоем, эквидистантным поверхности (`offset_grid` + `skin`).
6. Теоретическая поверхность для обводов — грани без толщины: `surface_face`, группа `theory`.

### Квадовый меш из сеток (`bp3d.mesh`)
CAD-триангуляция даёт длинные тонкие треугольники и веера без петель и развёртки. Жёсткому предмету это почти не мешает, а меш, который гнётся скелетом, на ней ломается. Второй путь строит полигональный меш из тех же сеток `(nu, nv, 3)`, что идут в `bspline_surface` и `skin`:

- ячейка сетки — квад; сетка не пересэмплируется: сколько рядов задано, столько петель и будет. Сгущение рядов — `spacing(n, dense=[(центр, полуширина, во_сколько_раз)])`;
- лоскут (`Patch`) — UV-остров, развёрнутый по длинам рядов; масштаб островов один, поэтому плотность текселей одинаковая. Острова раскладываются в общий атлас модели при сборке;
- общий ряд соседних лоскутов сваривается; толщина — второй слой по нормалям вершин («на ус» на изломе) и торцевые квады по кромкам;
- B-rep для чертежа строится из тех же сеток (`QuadMesh.brep()`), поэтому чертёж и модель по-прежнему сняты с одного построения. Разрезы квадовых деталей снимаются с самого меша.

| Функция | Что строит |
|---|---|
| `quad_skin(bands, t)` | Аналог `skin`: панель с толщиной из лоскутов с общими рядами; `t=0` — один слой (двусторонний материал); `closed_u=True` — труба |
| `quad_shell(patches, t)` | Оболочка из готовых `Patch` |
| `quad_tube(G)` | Сплошное тело из сетки колец с заглушками квадами |
| `quad_sweep(profile, path, corners=...)` | Профиль вдоль кривой (пояс, ручка, кант); `corners` — острые углы профиля, `closed_path` — кольцо |
| `revolve_quad(profile, center, axis, n)` | Тело вращения; точки на оси дают полюса (веера треугольников) |
| `box_quad`, `sweep_grid`, `loft_grid`, `revolve_grid`, `cap_grid` | Коробка с острыми рёбрами и сетки для своих построений |
| `Path.sample(step)` | Точки контура `Path` с сохранением вершин — профиль для свипа и вращения |

Деталь добавляется как обычно: `M.add("body", 1, "Корпус", "Сталь", quad_mesh, color="teal")`. Отчёт сборки показывает по деталям число квадов и треугольников, отклонение квадов от B-сплайна той же сетки, растяжение развёртки и плотность атласа (px/см); в `out/model/` добавляются рендеры каркаса `render_wire*.png` и текстура `<имя>_atlas.png`. Образец — `examples/quad_parts`.

Пороги `check`: соотношение сторон квада не больше 8:1 (торцы кромок не считаются: они вытянуты по построению), отклонение от B-rep больше 1,5 мм — предупреждение «добавить рядов». Треугольники допустимы только на полюсах вращения и носках — их число видно в `check` и в отчёте.

### Складки и мелкий рельеф (`bp3d.folds`)
Общая возможность для любого квадового меша (одежда, мягкие предметы). Складка — часть модели: при анимации она не меняется, вещь только гнётся по костям.

Складка (`Fold`) — кривая на поверхности: `path` (точки, мм; при сборке детали прижимаются к поверхности) или `uv=[(u, v), ...]` на лоскуте `patch` (по имени) — плюс профиль сечения: `ridge` (скруглённый гребень), `valley` (скруглённая впадина), `pipe` (широкий гребень), `crease` (острый залом), `groove` (острая канавка, шов), `step` (ступень — залом сложенной ткани), `stitch` (пунктирная канавка с шагом `pitch`). Параметры: `amp` (мм, плюс — наружу; число, `(в начале, в конце)` или по точкам кривой), `width` (полуширина профиля, мм), `taper` (затухание к концам, доля длины), `asym` (−1…1), `offset` (мм поперёк кривой — параллельные строчки от одного шва), `closed`.

`mode` — куда идёт складка; можно несколько сразу, а разные складки одной вещи — разными способами:

| Режим | Куда | Для чего |
|---|---|---|
| `geo` | В геометрию игровой модели; сетка у складки сгущается сама (`refine_for_folds`) | Крупные складки: гармошка у щиколотки, «мешки» у колена, натяжение, висящие «трубы» |
| `normal` | В карту нормалей (`<имя>_normal.png`, касательное пространство OpenGL Y+), запекается по развёртке | Мелкие складки, присборка, швы, строчка, рубчик резинки |
| `mask` | В маску складок для художника (`<имя>_foldmask.png`, яркость — сила складки) | Данные для прорисовки или затенения складок |

Складки передаются в `Outfit.add(..., folds=[...])`; блок может нести свои (`Piece.folds`: рубчик пояса-резинки). Карта нормалей запекается аналитически по полю складок в точке поверхности под каждым пикселем — это то же, что запекание с высокополигональной версии той же вещи; сама высокополигональная версия не выгружается. Разрешение атласа — `Model.atlas_px` (по умолчанию 2048; для строчки и рубчика — 4096).

- Сгущение добавляет ряды только поперёк складки (кольцевой складке нужны частые ряды, а не колонки вдоль неё), не больше `REFINE_MAX` = 4 между двумя старыми и не делает квад уже 1:`REFINE_ASPECT` = 5. Направление, кромки которого сварены с другим лоскутом, не сгущается — печатается заметка (поднять `cols` / уменьшить `row_step` блока).
- Точки, сдвинутые складками `geo`, выталкиваются из тела до отступа слоя.
- На готовом теле (`Piece.solid`: обувь, шнурки) работают только `normal` и `mask`.

### Правила, выведенные на практике
- **Ориентация сетки.** Нормаль лоскута — `du × dv`. `skin` наращивает толщину в сторону «минус нормаль». Слой «внутрь» на сетке с нормалью наружу уйдёт наружу: развернуть сетку (`G[:, ::-1]`) и проверить габарит в `check` — он не должен вырасти.
- **Зеркальные детали** — `mirror_y` готовой левой детали, а не построение второй сетки с обратным обходом.
- **`union` не всегда надёжен** на сплайновых телах: может потерять тело или дать невалидный результат. Проверять объём и `is_valid`; если не складывается — оставить отдельной деталью той же позиции (`count=False`).
- **Тела перекрываются, а не касаются.** Касание гранями даёт незамкнутый меш после сварки.
- **Невалидное тело** после булевых операций — `heal(...)`. Оно ломает повторную полигональную проекцию.
- **Сетка зоны — с запасом.** Деталь у края сетки обрезается молча (получается обрезок вместо диска).
- **Завалы и скругления кромок** считать по фактическому расстоянию до кромки, а не интерполяцией между соседними линиями — иначе кромка идёт волной.
- **За каждым проёмом — глухая стенка** (решётка, ниша, колёсная арка). Линии чертежа просвет не покажут, рендер покажет.
- **Внутренние узлы не пересекают внешние.** Проверять в разрезах и в черновой 3D.
- **Поверхность через сетку строит `kit.bspline_surface`** своей интерполяцией. Штатный интерполятор OpenCascade (`GeomAPI_PointsToBSplineSurface`) несимметричен: на зеркальной сетке давал у одного края волну в несколько миллиметров — складку у стыка только с одной стороны. Не возвращаться к нему.
- **Симметрию проверять с обеих сторон.** Симметричная сетка ещё не значит симметричное тело: сравнивать левый и правый стык на крупном рендере черновой сборки, а при сомнении — лучами (`find_intersection_points`) в зеркальных точках. Сравнение объёмов половин местную волну не ловит.
- **Щели вдоль кромок.** Деталь, которая должна примыкать к криволинейной панели (подкрылок к борту), задавать по форме этой панели, а не постоянной шириной.
- **Плоская панель** на чертеже почти не видна, в 3D бросается в глаза. Проверять стрелу выпуклости по теоретическим обводам: числа важнее впечатления от линий.
- **Острый профиль — лоскутами.** B-сплайн через сетку скругляет углы: прямоугольное сечение ремня одним лоскутом превратилось в овал с отклонением 1,7 мм. Углы профиля задавать через `corners` в `quad_sweep` (каждая грань — свой лоскут, ребро острое).
- **Замкнутый профиль вращения** идёт от оси до оси: первая и последняя точки с радиусом 0, иначе меш не замкнут.
- **У лица и изнанки оболочки — общая диагональ квада.** Квад двоякой кривизны неплоский, движок делит его на два треугольника по диагонали от первой вершины. Изнанка с обходом «задом наперёд» делилась по другой диагонали и выступала сквозь лицо точками цвета подкладки. Обход изнанки — с той же первой вершины.
- **Поля в атласе — не меньше 10 px и фон цветом ближайшего острова.** На mip-уровнях цвет соседа иначе затекает в мелкие острова.
- **Детали одной позиции не начинать в одной точке.** Две ленты из общей точки свариваются в ребро с тремя гранями (неманифолдный меш).

## Одежда

> **Одежда — в самом начале разработки.** Пайплайн одежды (тело, блоки одежды, веса, кости с пружиной, `posetest`) только начат: возможны глитчи — смятые или неровные кромки, детали, которые стыкуются нечисто, позы, где ткань проходит сквозь тело. Сейчас это нормально и будет исправляться шаг за шагом. Если нашли проблему, пожалуйста, [заведите issue](https://github.com/prizmor/blueprint3d/issues) со спецификацией и рендером или исправьте сами и пришлите pull request — см. [CONTRIBUTING.md](../CONTRIBUTING.md). Пайплайн жёстких предметов более зрелый.

Стиль — аниме-игры: одежда — это смоделированный меш с чистой квадовой топологией, а не симуляция ткани. Форму задаёт модель (юбка держит колокол, воротник стоит), движение дают кости с пружиной только там, где оно нужно (подол, ленты, хвосты), одежда сидит на теле, а тело под ней скрывается. Выкроек и сшивания нет: вещь описывается сразу в 3D относительно тела. Образец и шаблон — `examples/garment_basic`.

### Тело (`bp3d.body`)
```python
from bp3d import body
BODY = body.load(body.MANNEQUIN_F)        # .blend / .glb / .fbx с арматурой и весами
BODY.lm["waist"], BODY.measures["bust"]   # ориентиры и мерки; python -m bp3d body <файл>
```
- **Система координат персонажа** — та же, что у предметов: Z вверх от пола, X — назад (перёд смотрит в −X), левая сторона персонажа — −Y, миллиметры. После сборки в Blender перёд смотрит в −Y, левая рука — в +X, FBX пишется с осями Unity (как у предметов).
- Тело выгружается через Blender в фоне один раз и кешируется в `.cache/` (в git не входит); на стороне спецификации — только numpy.
- Поза покоя любая (A или T): всё считается от костей. Кости сводятся к **ролям** (`hips`, `spine`, `chest`, `upper_chest`, `neck`, `head`, `clavicle_L`, `upper_arm_L`, `forearm_L`, `hand_L`, `thigh_L`, `shin_L`, `foot_L`, `toe_L` и то же с `_R`) по именам — понимаются Unity Humanoid, Mixamo, UE/MakeHuman game_engine. Необычные имена: `body.load(path, roles={"thigh_L": "Bip_L_Thigh", ...})`.
- **Ориентиры** `BODY.lm`: высоты `waist`, `bust`, `underbust`, `hips`, `crotch`, `armpit`, `neck_base`, `head_base`, `knee`, `ankle`, `height`; точки суставов `shoulder_L`, `elbow_L`, `wrist_L`, `hip_L`, `knee_L`, `ankle_L`, `armpit_L`, `shoulder_top_L` (и `_R`); параметры конечностей `elbow_t`, `knee_t`. Считаются по костям и сечениям; переопределяются: `body.load(path, landmarks={"waist": 1050.0})`.
- Параметр конечности `t`: 0 — плечевой или тазобедренный сустав, 1 — запястье или щиколотка, локоть и колено — `lm["elbow_t"]`, `lm["knee_t"]`.
- Строительные блоки: `torso_ring(z)`, `torso_grid(zs, nu, offset, tent)` — оболочка туловища со смещением; `limb_ring`, `limb_grid(limb, ts, nu, offset)` — оболочка руки или ноги; `section(origin, normal)` — сечение тела; `closest(P)` — расстояние до тела со знаком; `push_out(G, clearance)` — вытолкнуть сетку из тела до зазора; `weights_at(P)` — веса с ближайшей поверхности.
- **Хеш тела входит в апрув.** Хеш файла тела и таблиц ролей и ориентиров входит в хеш спецификации: тело изменилось — апрув устарел.

Тела инструмента: `bodies/mannequin_f` — женская фигура MakeHuman (MPFB2, базовый меш и скелет game_engine на 53 кости, A-поза), лицензия ассетов CC0 — см. `bodies/README.md`; `bodies/dummy_t` — манекен кодом (T-поза, имена Unity Humanoid), второе тело для проверки, что вещь не привязана к одному ригу.

### Блоки одежды (`bp3d.garment.Outfit`)
`O = Outfit(M, BODY)` ставит тело в модель и добавляет его обстановкой на чертёж. Каждый блок возвращает `Piece` — сетки наружной поверхности с именованными кромками (`edges`), к которым стыкуются другие блоки. `O.add(key, pos, name, material, [блоки], finish, color, layer, bind, dynamics, hides, pattern)` сваривает блоки по общим рядам в одну деталь с толщиной.

| Блок | Что это | Кромки |
|---|---|---|
| `tube(top, bottom)` | Оболочка туловища без плеч: корсаж, бандо, кокетка | `top`, `bottom` |
| `bodice(bottom, neck, ...)` | Лиф, топ, рубашка, блуза, жакет, жилет: труба до подмышек и верх с плечами. `neck`: `round`, `v`, `square`, `boat`, `high`; `open_front=True` — распашной перёд | `bottom`, `neck`, `armhole_L/R` |
| `sleeve(top, side, length, kind)` | Рукав от проймы: `straight`, `flare`, `bell`, `puff` (фонарик), `cap` (крылышко); без рукава — блок не добавлять | `end` |
| `skirt(waist, length, kind)` | Юбка: `straight`, `a`, `bell`, `circle`; `pleats=n` — складки геометрией; `top=лиф` — платье одной деталью | `waist`, `hem` |
| `pants(waist, length)` | Брюки, шорты, леггинсы: таз, шаговый мостик, две штанины. Свободный крой: `ease` по ориентирам (`{"waist": 0.5, "hips": 10}` — резинка на талии, свободно на бёдрах), `leg_ease` по зонам `top`, `thigh`, `knee`, `calf`, `ankle`, `leg_around` по сторонам `front`, `back`, `out`, `in`, `leg_tent`, `leg_smooth`, `crease` (предел отступа под коленом и спереди у паха, по умолчанию 12 мм), `elastic=True` | `waist`, `end_L/R` |
| `stocking(side, top, bottom)`, `glove(side, ...)` | Чулок, гольф, носок; нарукавник | `top`, `end` |
| `collar(top, kind)` | Воротник по вырезу: `stand` — стойка ровным кольцом вокруг оси шеи (`height`, `front_drop` — насколько ниже спереди, в долях высоты); её низ идёт точно по кромке выреза лифа, `turndown`, `flat`, `ruffle` | |
| `cuff(piece, kind)`, `hem_band(piece, kind)` | Манжета и кайма: `band`, `turnback`, `ruffle` | |
| `band(loop, profile)` | Любая полоса вдоль кромки: свой профиль, волна (оборка, рюш) | |
| `piping(loop)` | Кант — шнур вдоль кромки | |
| `belt(z, width, over=[...])` | Пояс; `over` — вещи под ним: пояс ложится на них | `ring`, `front` |
| `buckle(center, normal, up)` | Пряжка — тело build123d (`mesh="cad"`), ложится на пояс с его наклоном: `center=belt.edges["front"]`, `normal=belt.edges["front_normal"]`, `up=belt.edges["front_up"]`; добавляется `M.add(..., bind="hips")` | |
| `buttons(z_top, z_bottom, count)`, `lacing(...)` | Ряд пуговиц и шнуровка по переду или спине | |
| `ribbon(path, width, over=[...])` | Лента вдоль ломаной; `over` — вещи, на которые она ложится | `end` |
| `bow(center)` | Бант: петли с узлом и два хвоста отдельными блоками (хвостам — динамика) | |
| `shoe(side, shaft)` | Ботинок или сапог на колодке: голенище и изгиб у щиколотки идут по ноге, от подъёма до носка — своя гладкая форма (огибающая стопы плюс `ease`, носок закруглён на доле длины `toe`, высота носка не меньше `toe_height`); подошва-чаша толщиной `sole` с рантом `welt` и бортиком `rand`, поднимающимся по стенке верха, — отдельный лоскут `<имя>_sole` | `top` |
| `binding(piece, edge, width)` | Окантовка, обнимающая кромку с обеих сторон (вырез, пройма); направление поперёк кромки — по поверхности вещи | |
| `waistband(piece, width)` | Пояс на резинке поверх верхней кромки брюк или юбки; ложится на вещь, рубчик резинки — в карте нормалей | |
| `sneaker_details(shoe, tongue_w, eyelets)` | Детали кроссовка на блоке `shoe`: мягкий кант, язычок по подъёму, шнуровка с люверсами; возвращает (блоки материала ботинка, блок шнурков) | |
| `auto_folds(piece, amount, seams)` | Правдоподобная расстановка складок по типу блока и посадке (`pants`, `sleeve`, `skirt`): гармошка у колена и щиколотки, натяжение от паха, висящие «трубы», присборка под резинкой, боковой и шаговый швы | |
| `folds_accordion`, `folds_tension`, `folds_hanging`, `folds_spiral`, `folds_gather`, `fold_crease`, `folds_pressed`, `folds_quilt`, `seam` | Типы складок готовыми функциями (гармошка от сжатия, натяжение, висящие, спиральные, присборка, залом сложенной ткани, заутюженные, простёжка, шов со строчкой); `limb_arc`, `limb_line` — кольца и линии вдоль конечности для своих складок | |

- **Слои.** `layer` 1 — у тела (облегающее, чулки), 2 — верх и юбки, 3 — верхняя одежда, 4 — аксессуары. Отступ изнанки от тела растёт по слоям: 2, 6, 10, 14 мм (`garment.LAYER_GAP`), поэтому слои не пересекаются. `ease` — прибавка свободы поверх отступа: число, функция высоты или `{"waist": 2, "bust": 6}`. `tent` 0…1 — натяжение ткани через впадины (ложбинка, между ног).
- **Плотность сетки.** `cols` — петель вокруг туловища (кратно 8), `row_step` — шаг рядов, мм (по умолчанию 20). У талии, локтя и колена ряды сгущаются сами; `check` требует не меньше 3 петель поперёк сгиба.
- **Привязка.** Стратегии (`bind`):
  - `"auto"` / `"tight"` — облегающая: веса с ближайшей поверхности тела с интерполяцией внутри треугольника;
  - `"proxy"` / `"loose"` — свободная: где ткань отходит от тела, веса берутся с прокси-тела (`Body.proxy`: тело, раздутое на 25 мм и сглаженное, с весами, сглаженными по сетке 12 раз); где прилегает (резинка, пояс) — с кожи. Смешивание — по зазору: ближе `rig.PROXY_FROM` = (10, 22) мм — кожа, дальше — прокси, между — плавно;
  - имя кости или роль — жёсткая деталь на одной кости.

  После переноса веса сглаживаются по ткани на расстояние (`smooth_mm`, неявная диффузия с весом ребра 1/длина²): `rig.SMOOTH_MM_TIGHT` = 20 мм для облегающих, `SMOOTH_MM_LOOSE` = 45 мм для свободных; у свободных влияния меньше `WEIGHT_MIN_LOOSE` = 0,03 мягко отбрасываются. Остаётся 4 влияния на вершину. Вершина слева не берёт веса с правой руки и ноги. Свои значения: `bind=dict(mode="loose", smooth_mm=30, inflate=25, proxy_smooth=12, proxy_from=(10, 22), w_min=0.03)`. Жёсткая деталь — `bind="hips"` (роль или имя кости).
- **Динамика.** `dynamics="stiff" | "soft"` или словарь: `preset`, `patch` (имя лоскута), `chains` (цепочек вокруг; у ленты 1), `bones` (костей в цепочке), `v0`…`v1` — участок сетки сверху вниз, где работает динамика, `blend` — ширина перехода от весов тела, `parent` — кость корня, `radius` — радиус столкновения, `follow` — доля поворота бедра, которую повторяет корень цепочки, `colliders`. Юбка сама подставляет умолчания: корень на тазе, старт у линии бёдер, 12 цепочек по 4 кости, `follow=0.9`, коллайдеры — только ноги и таз. Коллайдеры-капсулы тела (бёдра, голени, плечи, предплечья, таз, туловище, голова) строятся автоматически.
- **Скрытие тела.** `hides=True`: вершина тела ближе 14 мм к изнанке вещи и дальше 18 мм от её кромок считается закрытой; полигон тела скрывается, если закрыты все его вершины. Настройка — `hides=dict(reach=…, margin=…)`.

### Что получается после `build`
`out/model/`: `<имя>.blend`, `<имя>.fbx` (арматура тела с добавленными костями динамики, меши одежды с весами, `Body_masked` — тело со срезанными скрытыми полигонами; `add_leaf_bones=False`, оси Unity), `<имя>.glb`, `<имя>_atlas.png`, `<имя>_dynamics.json`, рендеры (`front`, `back`, `side`, `q`, `bodice`, `sleeve`, `hem`, `wire_*`) и `report.json`.

- **Тело и одежда.** В FBX идут одежда и готовое тело со срезанными полигонами — его можно сразу поставить в сцену. Для сменных костюмов Unity берёт из FBX только меши одежды, а полигоны общего тела прячет по списку `hidden_polys` из `manifest`/`report` (номера полигонов исходного меша тела). Маска текстурой по UV тела не делается.
- **Кости с пружиной.** Инструмент не привязан к компоненту движка, поэтому параметры лежат в нейтральном `<имя>_dynamics.json`: цепочки (кости, родитель, `stiffness`, `damping`, `gravity`, `hit_radius_m`, длины, `follow`, список коллайдеров) и капсулы-коллайдеры (кость, радиус, начало и конец в долях длины кости). Варианты для Unity: UniVRM SpringBone (MIT), Magica Cloth 2 (BoneSpring), свой компонент по этому файлу; в других движках — свой компонент по тому же файлу.

### Проверки одежды
- `check` — к проверкам квадов добавляются: ни одна точка не внутри тела в исходной позе (ошибка), зазор не меньше половины отступа слоя (предупреждение), петли в зонах суставов.
- `posetest` — модель ставится в 12 поз (`rest`, `t_pose`, `arms_down`, `arms_up`, `arms_forward`, `elbows_bent`, `squat`, `wide_step`, `side_step`, `bend_forward`, `twist`, `sit`) тем же линейным скиннингом и теми же весами, что уходят в FBX; кости с пружиной занимают положение равновесия (пружина к позе покоя, тяжесть, выталкивание из коллайдеров наружу от тела). Считается:
  - `тело` — вершина одежды ушла под кожу своей части тела (скрытые полигоны не считаются);
  - `слой` — вершина верхнего слоя ушла под наружную поверхность нижнего слоя на той же части тела;
  - `коллайдер` — насколько коллайдер отодвинул сустав цепочки (справочно: большая величина — подол лежит на бедре).
  - `растяжение` / `сжатие` — насколько ребро наружного слоя растянуто или сжато сильнее кожи под ним (линейный скиннинг сам тянет кожу манекена у подмышки в позе `arms_up` в разы, и облегающая вещь не может тянуться меньше). Пороги: `posetest.STRETCH_MAX` = 60 %, `COMPRESS_MAX` = 70 %, в крайних позах `STRETCH_EXTREME` = 90 %; по зонам (`STRETCH_ZONES`, ближайший ориентир): пах 110 %, подмышка 90 %, локоть и колено 75 %. Все пороги — предложение;
  - `кожа в теле` — ткань вошла в кожу, которая сама ушла в другую часть тела в позе (икра в бедро в приседе, живот в бедро сидя: линейный скиннинг сминает внутреннюю сторону сильного сгиба). Показывается отдельно и в провал не идёт: это предел позы, а не вещи (`posetest.skin_self`).
  Цепочки одной зоны динамики связаны как полотно: сустав подтягивается к смещению соседних цепочек на долю `posetest.LATERAL` (0,75), если соседи смещены сильнее, — подол не провисает клином между бёдрами.
  Таблица «поза → деталь → вид → глубина → место (ближайший ориентир)» печатается и пишется в `out/posetest/report.json`; рядом — кадр каждой позы и крупные планы четырёх худших мест.
- **Пороги** (`posetest.PEN_BODY`, `PEN_LAYER`, `PEN_EXTREME`): 4 мм для тела и слоёв; 12 мм в крайних позах `sit`, `squat`, `elbows_bent` — там сустав согнут больше чем на 90°, тело при линейном скиннинге само входит в себя в складке, и одежда в складке это повторяет. Что глубже порога — исправлять: отступ (`ease`), слой, длину, привязку, динамику.
- Поза показа — `posetest.HERO` (стоя, вес на одной ноге, руки расслаблены); позы задаются поворотами костей в коде: `("to", вектор)`, `("bend", градусы, вектор)`, `[("z", градусы)]`.

### Правила одежды, выведенные на практике
- **Рукав не заканчивать на локте, штанину — на колене.** Край у самого сустава при сгибе входит в соседний сегмент (манжета на локте дала 30 мм в `elbows_bent`). Край — выше или ниже сустава на 0,1 параметра.
- **Пояс — по весам тела, не на одной кости.** Пояс на `hips` врезался в талию на 28 мм в приседе: талию ведут кости позвоночника. На одну кость — только мелкие жёсткие детали (пряжка).
- **Корень цепочки — на кости, которая ведёт вещь под ней.** Подол — на тазе, лента на груди — на грудном отделе. Лента у пояса с корнем на тазе уезжала от шорт при повороте корпуса на 15 мм, с корнем на позвоночнике — при наклоне.
- **Динамика юбки начинается у линии бёдер, а не у талии.** Выше юбка идёт за телом вместе с поясом; старт у самой талии даёт сдвиг пояса при наклоне.
- **Накладная деталь ложится на одежду, а не на тело.** Лента у ворота, посчитанная от тела, оказалась на 12 мм под футболкой: у ложбинки ткань натянута (`tent`). Передавать `over=[вещь]`.
- **Короткая юбка и поза «сидя».** Бедро поднимается на 90°, и подол должен лечь на него: помогают `follow`, больше цепочек, `radius` 30. Цепочка между бёдрами коллайдеров не касается; в оценке её тянут за собой соседние цепочки (`posetest.LATERAL`), иначе перёд провисает клином сквозь ноги. В движке для этого нужна связь между соседними цепочками (поле `ring` в `<имя>_dynamics.json`) — смотреть кадр `pose_sit`.
- **Стойку воротника не обтягивать по точкам.** Выталкивание каждой точки стойки из тела мяло её, делало верхнюю кромку неровной и вытягивало вверх под подбородком. Стойка строится кольцами вокруг оси шеи: постоянный зазор, плоская верхняя кромка, спереди ниже.
- **Подошва стыкуется с верхом бортиком.** Плоская плита под верхом выглядела приклеенной снизу. Подошва — чаша: низ верха утоплен в неё, бортик `rand` поднимается по стенке.
- **Стойка начинается с кромки выреза.** Стойка поверх выреза со своей сглаженной кромкой оставляла щель и нахлёст с тканью лифа; кромку выреза и ткань у шеи лиф выравнивает сам, а стойка берёт те же точки.
- **У обуви своя форма, а не обтяжка стопы.** Оболочка по стопе повторяла пальцы и свод. От подъёма до носка обувь строится на колодке; тело внутри неё может быть любым.
- **Жёсткую накладку ставить по наклону вещи под ней.** Пряжка, стоящая вертикально, на наклонном поясе выглядела посторонней: брать нормаль и «верх» у пояса.
- **Коллайдеры подола — ноги и таз.** Капсула туловища при наклоне вперёд приходит сверху и толкала подол вверх, в жилет.
- **Зазор проверять и между вершинами.** Плоский квад срезает выпуклость тела: `push_out` отодвигает и углы ячейки, середина которой ближе половины отступа.
- **Скрытие тела не доходит до кромки.** Полоса тела у края вещи остаётся видимой (`margin`): иначе в вырезе и под подолом видна дыра.
- **Сглаживать веса по расстоянию, а не по соседям.** У рукава под мышкой перепад весов пришёлся на несколько рёбер по 6 мм, и в позе `arms_up` они тянулись на 280 % сверх кожи; сглаживание на 20 мм ткани дало 55 %.
- **Хвост далёкой кости хуже, чем никакого веса.** 3,7 % бедра на вершине живота сдвигали её на 9 мм сидя (бедро поворачивается на 90°), а у соседней вершины четвёртым влиянием была другая кость. У свободных вещей мелкие влияния отбрасываются мягко (`WEIGHT_MIN_LOOSE`); жёсткое отсечение даёт скачок на границе отсечения.
- **Прокси-тело — только там, где ткань висит свободно.** Прокси-веса у резинки на талии тянули бедро в живот и растягивали его на 289 %; они подмешиваются по зазору до тела.
- **Свободная ткань на внутренней стороне сгиба проваливается в тело.** Под коленом в приседе и спереди у паха сидя линейный скиннинг сминает сгиб; отступ там ограничен (`pants(crease=...)`).
- **Узкой полосе — густая кромка.** Окантовка на редкой кромке выреза давала квады 1:15; кромка пересэмплируется под шаг поперёк полосы, линейно — кубический сплайн перехлёстывает на углах лямок.
- **Поперёк кромки — по поверхности вещи.** Средняя плоскость проймы уводила окантовку в тело под рукой: пройма — пространственная кривая.
- **Пояс-резинка ложится поверх брюк.** Ниже кромки брюки расширяются к бёдрам, и прямая лента проваливалась в них; присборка начинается под поясом.
- **Натяжение (`tent`) — ниже корня конечности.** У паха хулл кольца захватывал таз и раздувал штанину до 45 мм.

## Лист

| Ключ в `sheet()` | Назначение |
|---|---|
| `views` | Виды: `kind` (`side`, `front`, `top`, `rear`, `right`, `iso`), `k`, `at`, `look_at` |
| `views[].parts`, `exclude`, `groups` | Вид части деталей, например узел в сборе отдельно |
| `views[].grid` | Тонкая сетка сечений поверх вида: батоксы, горизонтали |
| `plans` | Теоретические обводы: наложенные сечения плоскостями без проекции тел |
| `sections` | Разрезы; `behind` — что видно за секущей плоскостью на заданную глубину |
| `details` | Выносные виды из готового вида |
| `dims`, `dias`, `radii`, `angles` | Размеры: линейные, диаметры, радиусы, угловые |
| `balloons`, `notes`, `texts`, `lines`, `cuts` | Позиции, выноски с текстом, подписи, осевые, обозначения разрезов |
| `gaps`, `tech` | Таблица зазоров, технические требования |
| `hlr="poly"` | Полигональный расчёт скрытых линий: секунды вместо минут на сборках из сотен сплайновых тел. По умолчанию — точный |
| `views[].dynamics` | Одежда: линии цепочек костей с пружиной и граница зоны динамики на виде |
| `views[].folds` | Одежда: линии складок режима `geo` на виде, только на обращённой к зрителю стороне (гребень — штрих с точкой, впадина и залом — короткий штрих) |
| `sections[].plane = ("free", точка, нормаль[, верх])` | Разрез произвольной плоскостью (рукав поперёк руки); `near` — только контуры ближе стольких мм к точке |
| `measures_at`, `layers_at`, `dyn_at` | Одежда: таблицы мерок тела, слоёв и привязки, динамики |
| `size`, `legend_at`, `tech_at`, `gaps_at` | Формат листа в мм (по умолчанию А1 841×594; шаблон — А2 594×420) и места легенды, техтребований, таблицы зазоров. На листе меньше А1 `legend_at` задавать обязательно: место по умолчанию рассчитано на А1 |

Тело персонажа на листе — обстановка (`group="phantom"`): на видах рисуется его видимый контур, в разрезах — кольцо сечения, поэтому в разрезе видны отступ вещи от тела и её толщина. Лист одежды — А1, главные виды 1:5 (см. образец).

Узкие сечения (тонкий лист) зачерняются по ГОСТ 2.306. Точка проекции собственной камеры задаётся через `CAMERAS["имя"] = (направление, верх)`; для таких видов `look_at` оставлять `(0, 0, 0)` и считать `at` через `ViewProj(...).uv(точка)`.

## Самопроверка

**Чертёж** — смотреть PNG крупно, по зонам (`crop`):
- наложения текста, выносок и линий;
- размеры и выноски указывают туда, куда должны, цифры совпадают с моделью;
- виды согласованы, нет шальных линий и «дыр»;
- разрезы читаются: тонкий лист зачернён, детали не пересекаются;
- по обводам нет плоских участков там, где должна быть выпуклость.

**Модель** — отчёт и рендеры:
- незамкнутых мешей нет, отклонение габаритов в пределах 3 мм;
- общий габарит совпадает с задуманным;
- нет просветов насквозь, деталей наизнанку и торчащих полок;
- узнаётся ли объект без подписей.

**Одежда** — дополнительно:
- `check` без ошибок; на каркасе (`render_wire_*`) петли ровные, без вытянутых и скрученных квадов, у суставов гуще;
- `posetest` пройден; кадры поз и худших мест просмотрены глазами;
- силуэт фигуры читается, вещь не выглядит краской на теле: есть толщина, кромки, отступ;
- кожа не просвечивает сквозь ткань, в вырезах и под подолом нет дыр в теле;
- цвета и узор на месте, полосы идут вдоль петель.

## Рендер

`bl_render.py` назначает процедурные PBR-материалы по отделке деталей, ставит софтбоксы и рендерит в Cycles шесть кадров: главный, спереди, сбоку, сверху три четверти, фара и колесо крупно. Исходный `.blend` модели не меняется. Цвета окраски: `graphite`, `teal`, `coral`, `sand`, `white`, `black`; палитра — предложение, цвет выбирает пользователь.

Это показ формы и отделки, а не игровые текстуры. CAD-деталям для движка нужны ретопология, развёртка и карты — отдельным шагом пайплайна вашего проекта; квадовые детали уже идут с петлями, развёрткой и атласом цвета.

**Одежда** рендерится `bl_pose.py`: поза показа в toon-стиле (EEVEE: две ступени света через Shader to RGB, жёсткий блик у кожи и металла, обводка вывернутой оболочкой), тот же кадр матовый (Cycles) и каркас. Файлы — `out/render/hero_toon.png`, `hero_toon_back.png`, `hero_toon_side.png`, `rest_toon.png`, `hero_matte.png`, `hero_wire.png`. Это превью, а не игровой шейдер.

Нормали в модели — точные из CAD. Не пересчитывать сглаживание по углу и не «чистить» триангуляцию: это даёт пятна и изломы.

## Доработка инструмента

Чего не хватает — добавлять в `bp3d/` с комментариями, не ломая существующие спецификации. После любой правки `bp3d/`:

```powershell
& $py -m bp3d selftest --draw
```

Все образцы должны пройти; листы образцов после этого просмотреть глазами (`examples/<имя>/out/drawing/`). Новое правило или ограничение — сразу в этот файл (на обоих языках), новый приём — в образец или шаблон.

**Документация обязательна для каждой правки инструмента**: запись в `CHANGELOG.md` и все затронутые документы на обоих языках в том же pull request. Как устроен инструмент — [архитектура](architecture.ru.md), [модули](modules.ru.md), [команды](cli.ru.md), [форматы файлов](file-formats.ru.md); правила правок, проверок и документации — [руководство разработчика](development.ru.md).

## Что хранить в git

- **В репозитории инструмента:** код `bp3d/`, образцы, тела в `bodies/` (`.blend` через Git LFS и `macro.json`), документация, скрипты установки.
- **В вашем проекте:** `spec.py` и `approved.json` объектов, при желании `bp3d.json`. Всё из `out/` — чертежи, модели, рендеры — в git не нужно: оно воспроизводится командами из `spec.py`, хеш спецификации стоит на листе и в `report.json`. Добавьте в `.gitignore` проекта строку `out/`.
- Готовая модель попадает в движок отдельным шагом пайплайна проекта.
## Ограничения

- Лица, тела, волосы — другие инструменты. Симуляции ткани нет: складки — текстурой, шейдером или геометрией по параметру.
- Детали `mesh="cad"` — CAD-триангуляция без развёртки: серая модель и блокинг. Игровая топология — только у `mesh="quad"`.
- Характерные рёбра — острые изломы между лоскутами; радиусы на рёбрах пока не строятся.
- Импорт в движок не автоматизирован; компонент костей с пружиной в движке — на стороне проекта.
- Одежда: `posetest` — оценка на линейном скиннинге и статическом равновесии цепочек, а не игровая физика. Короткая юбка в позах «сидя» и «присед» даёт проникновения до порога крайних поз и выше.
- Одежда: распашной перёд (`open_front`) — без лацканов и застёжки внахлёст; чулок заканчивается у щиколотки (стопу закрывает обувь); каблука у ботинка нет, подошва уходит ниже пола на свою толщину (корень персонажа в игре поднимается на неё); на атласе торцы кромок делят один маленький остров.
- Одежда: свободные низы в глубоких сгибах — в `squat` ткань под коленом, сидя у талии и колена тянется выше порога, на широком шаге пах доходит до предложенного предела 110 %. Без корректирующих форм (не делались: решение пользователя) линейный скиннинг лучше не даёт; см. `posetest`.
- Одежда: складки — деформеров (изгиб, скручивание, раздувание, кисть) пока нет; складка на лоскуте со сваренными кромками сгущает сетку только по свободному направлению.
- Одежда: CAD-деталь привязывается только к одной кости.
