# Blueprint3D

**Чертёж кодом → 3D-модель один в один.** Объект описывается один раз — параметрической спецификацией на Python (`spec.py`), и из одной геометрии получаются и чертёж, и игровая 3D-модель. Что на чертеже, то и в модели.

[English](README.md) · [Документация](docs/README.ru.md) · [Руководство](docs/manual.ru.md) · [Архитектура](docs/architecture.ru.md) · [Команды](docs/cli.ru.md) · [Порядок для ИИ-агента](AGENTS.md)

| Результат | Что это |
|---|---|
| Чертёж | Лист по ГОСТ: SVG, PNG, PDF, белый и «синька». Проекции со скрытыми линиями, разрезы, выносные виды, размеры, выноски, спецификация |
| 3D-модель | `.blend`, `.fbx`, `.glb`, рендеры, отчёт. CAD-триангуляция (серая модель) или чистый квадовый меш с развёрткой прямо из сеток построения |
| Одежда | Вещи на теле с ригом: квадовая топология, развёртка, веса, кости с пружиной, скрытие тела, FBX с арматурой, проверка в позах с таблицей проникновений |

Подходит для жёстких предметов (транспорт, оружие, снаряжение, мебель, постройки) и для одежды персонажей в стиле аниме-игр (смоделированная вещь, а не симуляция ткани).

> **Одежда — в самом начале разработки.** Пайплайн одежды (тело, блоки одежды, веса, кости с пружиной, `posetest`) только начат: возможны глитчи — смятые или неровные кромки, детали, которые стыкуются нечисто, позы, где ткань проходит сквозь тело. Сейчас это нормально и будет исправляться шаг за шагом. Если нашли проблему, пожалуйста, [заведите issue](https://github.com/prizmor/blueprint3d/issues) со спецификацией и рендером или исправьте сами и пришлите pull request — см. [CONTRIBUTING.md](CONTRIBUTING.md). Пайплайн жёстких предметов более зрелый.

## Что нужно

- Git с [Git LFS](https://git-lfs.com/) — тела в `bodies/` лежат в LFS
- Python 3.12 (работают 3.10–3.13) или [uv](https://docs.astral.sh/uv/) — он поставит Python сам
- [Blender 5.3](https://www.blender.org/) — работает в фоне на 3D-этапе (build, render, posetest)
- Edge, Chrome или Chromium — печать листа из SVG в PNG и PDF (без браузера будет только SVG)

Основная платформа — Windows; Linux и macOS — через `scripts/install.sh`.

## Установка

```powershell
git lfs install
git clone https://github.com/prizmor/blueprint3d.git
cd blueprint3d
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Linux и macOS: `sh scripts/install.sh`.

Скрипт создаёт `venv/`, ставит build123d (OpenCascade), numpy и scipy и пишет, где нашёл Blender и браузер. Если Blender стоит в необычном месте — переменная `BP3D_BLENDER` с полным путём к программе; для браузера — `BP3D_BROWSER`.

Проверка:

```powershell
$env:PYTHONPATH = (Get-Location).Path
.\venv\Scripts\python.exe -m bp3d selftest
```

## Быстрый старт

```powershell
$env:PYTHONPATH = "C:\путь\к\blueprint3d"; $py = "C:\путь\к\blueprint3d\venv\Scripts\python.exe"
& $py -m bp3d new     art\blueprints\BOX-001 --title "Ящик"        # spec.py из шаблона
& $py -m bp3d check   art\blueprints\BOX-001                       # собрать и проверить тела
& $py -m bp3d draw    art\blueprints\BOX-001 --quick               # белый PNG для итераций
& $py -m bp3d build   art\blueprints\BOX-001 --force --out tmp\box # черновая 3D до апрува
& $py -m bp3d approve art\blueprints\BOX-001 --by "Имя" --note "Апрув"
& $py -m bp3d build   art\blueprints\BOX-001                       # итоговая модель по апрувнутому чертежу
```

Папки объектов лежат в **вашем** проекте, а не в этом репозитории. Результаты — в `<объект>/out/` (в git не класть: воспроизводится из `spec.py`). Необязательный `bp3d.json` в корне проекта задаёт значения листа по умолчанию, например надпись в штампе: `{"org": "СТУДИЯ"}`.

Все команды, формат спецификации, геометрия, одежда, ключи листа и чеклисты — в полном руководстве: [по-русски](docs/manual.ru.md) · [English](docs/manual.en.md).

## Участие — приходите

Если вы хороший геймдизайнер, хороший программист, 3D-художник или просто разбираетесь в этом лучше меня — присылайте pull request'ы. Лучше геометрия, топология и чертежи, новые блоки одежды, другие движки и платформы, понятнее документация, исправления ошибок — всё это нужно. Цель — чтобы инструмент развивался быстрее и давал результат всё выше качеством.

Как это устроено: форк, ветка, правка, `python -m bp3d selftest --draw`, обновить документацию и `CHANGELOG.md` (документация обязательна для каждой правки), pull request. Каждый pull request смотрит и вливает мейнтейнер. Подробно — [CONTRIBUTING.md](CONTRIBUTING.md).
